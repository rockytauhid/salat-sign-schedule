# SalatSign — Architecture & Product Decisions

This document records the confirmed product and architectural decisions (**D1–D25**) and working assumptions for **SalatSign** (`com.salatsign.tv`) and **SalatSchedule** (`com.salatschedule.tv`).

---

## Confirmed Decisions (D1–D25)

| # | Decision | Value |
|---|---|---|
| **D1** | Languages at launch | **English only (`en-AU`).** Keep the existing Indonesian text, extracted into `values-in/`, in the repository but **not shipped** until the owner (a native Indonesian speaker) has reviewed it (human task H5); use `androidResources.localeFilters` to ship `en` only until then. Arabic/RTL (`values-ar/`) is deferred (layout code uses `start`/`end` so RTL is cheap to enable later). *(Assumed: English-only launch until translations are reviewed.)* |
| **D2** | Default language and formats | English with **Australian spelling** (colour, centre, programme). Use `en-AU` for date and time formatting. **12-hour clock by default** (e.g. `5:12 am`) with a 12/24-hour setting. *(Assumed.)* |
| **D3** | Audience | **Australia first.** City presets list Australian cities first (Canberra, Sydney, Melbourne, Brisbane, Adelaide, Perth, Hobart, Darwin). **Daylight saving must be handled** (Sydney, Melbourne, Adelaide, Hobart, Canberra observe DST; Brisbane, Perth, Darwin do not; Adelaide and Darwin are on half-hour offsets). |
| **D4** | Calculation method | **No named preset.** The setup wizard asks for the calculation method and madhab. Preselect `MUSLIM_WORLD_LEAGUE` as a temporary default pending the owner's comparison with a local timetable (human task H4). *(Assumed.)* |
| **D5** | Adhan audio stream | Keep `AudioAttributes.USAGE_ALARM` and request transient audio focus; revisit after testing volume behaviour on the owner's Sony TV (human task H3). |
| **D6** | Custom assets | **Keep TV-side import** of custom adhan, mosque logo, and slide images from the TV's local storage or a USB drive. Imported files are copied into app-private storage (`filesDir/content/{images,logo,audio}`) with automatic orphan cleanup. |
| **D7** | Admin PIN | **Required in SalatSign (not used in SalatSchedule), default `0000`**, nudge the user to change it. Stored as PBKDF2-salted hash with progressive lockout; corrupted custom PIN storage locks settings and requires clearing app data rather than falling back to `0000`. |
| **D8** | Hijri rollover | **At Maghrib by default**, with an optional setting "Change date at midnight instead". Configurable day offset `-2` to `+2`. |
| **D9** | Digits | Latin digits (`0–9`), including when Arabic locale is eventually enabled (`ar-u-nu-latn`). |
| **D10** | Iqamah | In scope for **SalatSign**: per-prayer minutes after adhan (`0` or empty = disabled). Display only. When at least one is configured, SalatSign displays the Iqamah time; Friday Jumu'ah rows do not apply the Iqamah delay (the sitting time replaces it). |
| **D11** | License | **Copyleft: GPL-3.0-or-later** (`LICENSE`), plus a trademark/branding policy for the name "SalatSign" (`TRADEMARKS.md`). Copyright holder: Rocky Adam Tauhid (`rockytauhid@gmail.com`). |
| **D12** | Application ID | **`com.salatsign.tv` is final (confirmed by the owner).** Used for both `namespace` and `applicationId`; do not change either. |
| **D13** | Madhab | Chosen in the **setup wizard** and changeable in **Settings** (`SHAFI` / `HANAFI`). |
| **D14** | SalatSign audio/notifications | **Strictly silent** (superseded into compile-time isolation by D18): `:app-salatsign` declares zero audio, alarm, notification, or foreground-service permissions or code. |
| **D15** | Adhan audio files | Built-in `beep_beep.wav` alert plus per-prayer USB/local audio import (`MP3`/`WAV`/`M4A`/`OGG`) in **SalatSchedule** (`:app-salatschedule`), defaulting to `AdhanAudioType.SILENT` until the user selects Beep-Beep or imports a custom Adhan file. |
| **D16** | Jumu'ah (Friday) time | **Set by each mosque, not calculated. SalatSign only.** Configurable mode (`FIXED` clock time or `AFTER_ZUHR` minute offset) with up to 3 sittings inside the Zuhr-to-Asr window, validated across the next 53 Fridays (handling DST shifts). **SalatSchedule** always shows Friday as plain "Zuhr" with the calculated time. |
| **D17** | Two-app product focus | **SalatSchedule** (`com.salatschedule.tv`) and **SalatSign** (`com.salatsign.tv`) are two independent, first-class Android TV apps sharing `:core` and `:core-tv-ui` (see D18). SalatSchedule alarm reliability and real Adhan audio (`USAGE_MEDIA` + `AUDIOFOCUS_GAIN_TRANSIENT`) are release-blocking; SalatSign remains strictly silent with zero audio permissions. |
| **D18** | Multi-module product split | Split into two separate Android TV apps in a multi-module monorepo: **SalatSign** (`com.salatsign.tv`, `:app-salatsign`) is a **strictly silent** Mosque digital signage app (no audio/alarm/notification services or permissions; Jumu'ah, Iqamah, slides, branding, PIN, `FLAG_KEEP_SCREEN_ON`); **SalatSchedule** (`com.salatschedule.tv`, `:app-salatschedule`) is a dedicated Home prayer times app (Adhan audio, 15-min reminders, D-pad date browsing; no PIN, Iqamah, Mosque branding, slides, or Jumu'ah). Shared non-UI logic lives in `:core` (reusable by a future Android phone SalatSign controller) and shared Compose TV UI lives in `:core-tv-ui`. Per-app Play Store metadata lives in `docs/salatsign/STORE_LISTING.md` and `docs/salatschedule/STORE_LISTING.md`. |
| **D19** | Mosque Silent Screen (`:app-salatsign` only) | Always near-black (`#0E1110`) with soft near-white icons/text (≥ 7:1 contrast) even when Light Theme is active, using calm restrained sizing (`42 sp` title, `136 dp` icons, `24 sp` labels) and a `±6 px` burn-in pixel shift every 60 seconds so the TV does not draw attention during prayer. Uses `"Jumu'ah in progress"` for Friday Jumu'ah windows (shared duration `30–120 min`, default `45 min`, default ON when at least one sitting is configured) and `"Prayer in progress"` for optional per-prayer daily windows (default OFF, Friday Zuhr handled by Jumu'ah only) and manual override (`15 / 30 / 45 min`, persisted across restarts, available in both TV Settings and the Local Phone Controller). Starting manual mode from TV Settings auto-closes Settings immediately; tapping a remote key shows the neutral 4-second admin hint banner. Smart "Copy to all prayers" copies anchor/lead/duration to all 5 prayers and enables only prayers with a valid anchor (skipping `IQAMAH`-anchored prayers with `iqamah = 0`). |
| **D20** | 6-Slide Rotation Limit (`:app-salatsign`) | Total active slides in the Mosque slideshow rotation are capped at `MAX_ROTATION_SLIDES = 6` (`SlideBudget`), counting enabled announcement slides plus enabled built-in slides (Islamic Calendar = 1 slot, Quran Verse = 1 slot). The Prayer Schedule screen and Silent Screen do not count toward the 6. Stored library capacity remains 30 (`ContentRepository.MAX_SLIDES`) so admins can keep disabled slides. Legacy installs with > 6 enabled slides are never deleted; `SlideshowRotationBuilder` runs only the first 6 slots in order (announcements by `sortOrder`, then built-in slides) and Settings displays a warning listing hidden slides. |
| **D21** | Islamic Calendar Events (`:core`, `:app-salatschedule`, `:app-salatsign`) | All 16 Islamic events are computed on demand via `java.time.chrono.HijrahDate` using the exact inverse of `HijriCalendarEngine`'s display offset (`LocalDate.from(HijrahDate.of(y, m, d)).minusDays(offsetDays)`), with zero stored event data. `SalatSchedule` provides a full ±3-year navigable screen (entry button next to Settings + optional Home next-event line); `SalatSign` provides an optional read-only built-in slide (≤ 6 rows, 1 slot of 6, skipped when empty, suppressed during Silent Screen; scales gently from `32 sp` to `25 sp` when 5–6 rows appear so wrapped event names never clip or ellipsise on 1080p TV). Indonesian event names are tracked in `docs/i18n/islamic-events-id-pending.csv` pending owner review (`C1`). |
| **D22** | Offline Quran Verse Slide (`:core`, `:core-tv-ui`, `:app-salatsign`, `:app-salatschedule`) | 63 canonical verses (`tools/verse-list.txt`) extracted verbatim by `tools/build_quran_data.py` from official Tanzil.net Uthmani, Saheeh International (English), and Kementerian Agama RI (Indonesian) sources into bundled JSON assets (`core-tv-ui/src/main/assets/quran/`), with zero database and zero runtime network access. Rendered using bundled **Amiri Quran** (`res/font/amiri_quran.ttf`, SIL OFL 1.1) with auto-shrinking Arabic (`56 sp → 40 sp`, `1.85×` line height) and translation (`32 sp → 24 sp`), never truncating or ellipsising (skips on overflow and provides a 63-verse `"Check verse fit"` tool in SalatSign Settings). Uses a persisted no-repeat shuffle bag (`QuranShuffleBag`), auto duration `clamp(12 + 0.5 * wordCount, 15, 60)` (or fixed `10–90s`), occupies 1 of 6 rotation slots in SalatSign after Islamic Calendar, and is suppressed during Silent Screen. |
| **D23** | SalatSchedule Android TV Screensaver (`:app-salatschedule` & `:core-tv-ui`) | **SalatSchedule** (`com.salatschedule.tv`) implements an Android TV `DreamService` (`SalatScreensaverService`) plus a full-screen `ScreensaverPreviewActivity` and a **Screensaver** Settings category. To avoid creating a 5th Gradle module (`:slides-shared`) and keep build times fast, the shared Quran JSON assets, `amiri_quran.ttf`, `AssetQuranVerseRepository`, `SharedQuranVerseSlide`, and `SharedIslamicCalendarSlide` (5 upcoming rows) live in `:core-tv-ui` as the single source of truth for both apps. The screensaver is strictly silent, dark-only (`#060E0A` near-black), displays a minute-only clock, applies a ≤ 8 px burn-in pixel shift every 60 seconds, caches daily prayer/calendar data once per day, enforces at least 1 enabled slide, and exits immediately on any key press. |
| **D24** | Web-Only Phone Controller & Multi-TV Plan (`:core`, `:app-salatsign`) | No native companion app will be built; the TV-hosted web Phone Controller (`assets/phone_controller/`) is the primary remote UI (`docs/PHONE_CONTROLLER_PLAN.md`). Phase 0 establishes typed `kotlinx.serialization` API DTOs in `:core`, persistent TV identity (`deviceId`, `deviceName`, `roomGroup`), monotonic `configVersion` with `ETag`/`If-Match` (`412`) optimistic concurrency, and idempotent client-UUID slide writes. Future phases: (1) QR/code browser pairing with hashed tokens synced across the TV group and optional inactivity expiry (default Never); (2) Always-on boot startup by auto-launching `MainActivity` via `RECEIVE_BOOT_COMPLETED` (preserving D18's zero `FOREGROUND_SERVICE` / zero notification rule); (3) HMAC-signed TV-to-TV group sync where mosque content/settings/paired devices sync globally while TV identity/theme/always-on stay local, plus full-screen Urgent Notices yielding to Silent Screen (`Critical Emergency > Silent Screen > Urgent Notice > Schedule & Slideshow`); (4) Room-level slide sync (refined by **D25**). |
| **D25** | Wall-Clock Multi-TV Slide Sync (`:core`, `:app-salatsign`) | Replaces Phase 4's Leader/Follower network sync protocol with a pure, offline wall-clock scheduler (`WallClockSlideshowScheduler`) that maps `epochSeconds % totalCycleSeconds` to the active slide slot. Eliminates leader election, split-brain handling, LAN heartbeats, and clock-offset ping-pong while keeping TVs in the same mosque transitioning slides within ~1 second via Android NTP clocks (and remaining functional when Wi-Fi is down). Quran verse selection stays local per TV (`QuranShuffleBag`) with a fixed wall-clock slot duration (`25s` when Auto is selected, or configured `10–90s`) so verse-length differences or per-TV overflow skips never desynchronize the rotation cycle across TVs. |

## Working Assumptions

1. **Friday Adhan Timing (`SalatSchedule`):** Because `SalatSign` is strictly silent (D14/D18) and `SalatSchedule` always displays Friday as plain Zuhr (D16), `SalatSchedule` fires Friday's Adhan at the calculated Zuhr time (`AT_ZUHR`).
2. **Default Calculation Method (`MUSLIM_WORLD_LEAGUE`):** Preselected in the setup wizard and default `AppSettings` pending local Australian timetable comparison (H4).
3. **English-Only Launch (`en-AU`):** Only `en` resources are packaged in release APKs via `androidResources.localeFilters` until `docs/i18n/review-id.csv` is reviewed and approved by the owner (H5), and Arabic is reviewed by a native speaker.
4. **Target Hardware Floor (`minSdk 26`):** The primary physical test device is a **Sony KD-55X9300D** running **Android 8.0.0 (API 26)**. All APIs used in production code must exist on API 26 or be safely guarded with `Build.VERSION.SDK_INT` checks.
